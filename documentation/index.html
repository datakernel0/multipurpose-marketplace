Introduction

Welcome to MartPlace Next.js - a modern, fully-featured marketplace application built with Next.js 16, React 19, and TypeScript. This is a complete conversion of the original MartPlace HTML template, maintaining the exact same beautiful UI while leveraging modern React architecture and best practices.

Note: This documentation is for the Next.js version. The UI remains identical to the original HTML template, but all functionality is now powered by React and Next.js.

What's Included

  • Complete Next.js 16 application with App Router
  • TypeScript for type safety
  • PostgreSQL database with Prisma ORM
  • NextAuth.js authentication system
  • Real-time chat with Socket.io
  • Email functionality with Nodemailer
  • All original UI components and pages
  • Fully responsive design
  • SEO optimized

Features

Core Features

  • User Authentication: Registration, login, password reset with NextAuth.js
  • Product Management: Create, edit, delete products with image uploads
  • Shopping Cart: Add to cart, checkout, and order management

  • Admin Panel: Full admin interface for managing the marketplace

  • Reviews & Ratings: Product reviews and rating system

System Requirements

Server Requirements

To run MartPlace Next.js, your server must meet the following minimum requirements:

  • Node.js: Version 18.0.0 or higher (LTS version recommended)
  • npm: Version 9.0.0 or higher (comes bundled with Node.js)
  • PostgreSQL: Version 12.0 or higher (14.x or 15.x recommended)
  • RAM: Minimum 2GB (4GB or more recommended for production)
  • Disk Space: Minimum 500MB for application files (additional space for uploads and database)
  • CPU: 2 cores minimum (4+ cores recommended for production)

Development Requirements

For local development, you'll also need:

  • Git: For version control and cloning repositories
  • Code Editor: VS Code, WebStorm, or any modern IDE
  • Terminal: Command line access (Terminal on Mac/Linux, PowerShell/CMD on Windows)
  • Web Browser: Modern browser for testing (Chrome, Firefox, Safari, Edge)

Recommended Versions

For the best experience, we recommend using these versions:

  • Node.js: 20.x LTS (Long Term Support)
  • PostgreSQL: 15.x or 16.x
  • npm: 10.x (latest stable)
Note: You can check your Node.js version by running node --version and npm version with npm --version in your terminal.

Step-by-Step Installation Guide

Follow these steps carefully to install MartPlace Next.js:

Step 1: Extract Files

Extract the downloaded zip file to your desired location:

bash 
unzip martplace-nextjs.zip
cd martplace-nextjs

Step 2: Install Dependencies

Install all required npm packages:

bash 
npm install
Note: This may take a few minutes depending on your internet connection.

Step 3: Database Setup

Create a PostgreSQL database for the application:

sql 
CREATE DATABASE martplace;

Step 4: Environment Variables

The project includes a .env.example file that contains all the required environment variables with placeholder values. Copy this file to create your .env file:

bash 
# On Linux/Mac
cp .env.example .env

# On Windows
copy .env.example .env

Then edit the .env file and replace all placeholder values with your actual credentials:

env 
# Database
DATABASE_URL="postgresql://user:password@localhost:5432/martplace?schema=public"

# NextAuth Configuration
NEXTAUTH_URL=http://localhost:3000
NEXTAUTH_SECRET=your-secret-key-here-change-in-production

# Email Configuration (Nodemailer)
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-email@gmail.com
SMTP_PASSWORD=your-app-password
SMTP_FROM=noreply@martplace.com

# OAuth Providers (Optional)
GOOGLE_CLIENT_ID=your-google-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret
FACEBOOK_CLIENT_ID=your-facebook-client-id
FACEBOOK_CLIENT_SECRET=your-facebook-client-secret

# Application
NODE_ENV=development
NEXT_PUBLIC_BASE_PATH=""  # Optional: for subdirectory deployment
NEXT_PUBLIC_SITE_URL=http://localhost:3000
Important: Replace all placeholder values with your actual credentials. Never commit the .env file to version control. The .env.example file is safe to commit as it contains no sensitive information.
Note: The .env.example file serves as a template and documentation for all required environment variables. Always refer to it when setting up a new environment.

Step 5: Generate Prisma Client

Generate the Prisma Client for database operations:

bash 
npm run db:generate

Step 6: Run Database Migrations

Create the database tables:

bash 
npm run db:migrate

Step 7: (Optional) Seed Database

Populate the database with sample data:

bash 
npm run db:seed

Step 8: Start Development Server

Run the development server:

bash 
npm run dev

Open http://localhost:3000 in your browser.

Success! Your application should now be running. If you encounter any errors, check the Troubleshooting section.

App Router Structure

MartPlace Next.js uses the Next.js 13+ App Router, which provides a file-system based routing system with improved performance and developer experience.

Directory Structure

The app directory contains all routes and layouts:

text 
app/
├── layout.tsx          # Root layout (wraps all pages)
├── page.tsx            # Home page (/)
├── providers.tsx       # Client providers (SessionProvider, etc.)
├── (auth)/             # Auth route group
│   ├── login/
│   └── signup/
├── dashboard/          # Dashboard routes
│   ├── customer/
│   └── upload/
├── admin/              # Admin routes
│   ├── products/
│   ├── sellers/
│   └── customers/
├── api/                # API routes
│   ├── auth/
│   ├── products/
│   └── admin/
└── [dynamic]/          # Dynamic routes

Route Conventions

  • page.tsx: Creates a route segment (e.g., app/about/page.tsx → /about)
  • layout.tsx: Shared UI for a segment and its children
  • loading.tsx: Loading UI shown while page is loading
  • error.tsx: Error UI for error boundaries
  • not-found.tsx: 404 page for the route

Dynamic Routes

Use square brackets for dynamic segments:

  • app/product/[id]/page.tsx → /product/123
  • app/blog/[slug]/page.tsx → /blog/my-post

Route Groups

Use parentheses for route groups (don't affect URL):

  • app/(auth)/login/page.tsx → /login
  • app/(marketing)/about/page.tsx → /about

Layouts

Layouts wrap pages and persist across navigation:

typescript 
// app/layout.tsx (Root layout)

  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html>
      <body>
        {children}
      </body>
    </html>
  )
}

Metadata

Server vs Client Components

Next.js App Router uses React Server Components by default. Understanding when to use server vs client components is crucial for optimal performance.

Server Components (Default)

Server Components render on the server and are the default in the App Router:

  • Benefits: Smaller bundle size, direct database access, better security
  • Use for: Data fetching, accessing backend resources, large dependencies
  • Cannot use: useState, useEffect, browser APIs, event handlers

Example: Server Component

typescript 
// app/products/page.tsx (Server Component)
import { prisma } from '@/lib/prisma'

export default async function ProductsPage() {
  // Direct database access (server-side only)
  const products = await prisma.product.findMany()
  
  return (
    <div>
      {products.map(product => (
        <div key={product.id}>{product.title}</div>
      ))}
    </div>
  )
}

Client Components

Client Components render in the browser and require the "use client" directive:

  • Benefits: Interactivity, browser APIs, React hooks
  • Use for: Forms, buttons, interactive UI, useState/useEffect
  • Trade-off: Larger bundle size, runs in browser

Example: Client Component

typescript 
"use client"

import { useState } from 'react'

export default function Counter() {
  const [count, setCount] = useState(0)
  
  return (
    <button onClick={() => setCount(count + 1)}>
      Count: {count}
    </button>
  )
}

When to Use Each

Feature Server Component Client Component
Data Fetching ✅ Yes ❌ No (use useEffect)
Database Access ✅ Yes ❌ No
useState/useEffect ❌ No ✅ Yes
Event Handlers ❌ No ✅ Yes
Browser APIs ❌ No ✅ Yes
Third-party Libraries ⚠️ Depends ✅ Yes

Best Practices

  1. Start with Server Components: Default to server components unless you need interactivity
  2. Move Client Code Down: Keep client components as leaf nodes when possible
  3. Composition: Pass server-fetched data as props to client components
  4. Minimize Client Bundle: Only mark components as client when necessary

Example: Hybrid Approach

typescript 
// app/products/page.tsx (Server Component)
import { prisma } from '@/lib/prisma'
import ProductList from '@/components/ProductList' // Client Component

export default async function ProductsPage() {
  // Fetch on server
  const products = await prisma.product.findMany()
  
  // Pass to client component
  return <ProductList products={products} />
}

// components/ProductList.tsx (Client Component)
"use client"
export default function ProductList({ products }) {
  const [filter, setFilter] = useState('')
  // Interactive filtering on client
  return <div>...</div>
}

API Routes

API routes in Next.js App Router are defined in the app/api directory. Each route file exports HTTP method handlers (GET, POST, PUT, DELETE, etc.).

Route Structure

API routes follow the same file-system routing as pages:

text 
app/api/
├── products/
│   ├── route.ts           # GET /api/products, POST /api/products
│   └── [id]/
│       └── route.ts       # GET /api/products/:id
├── auth/
│   └── [...nextauth]/
│       └── route.ts       # NextAuth.js routes
└── admin/
    ├── products/
    └── dashboard/

Basic API Route

typescript 
// app/api/products/route.ts
import { NextRequest, NextResponse } from 'next/server'
import { prisma } from '@/lib/prisma'

// GET /api/products
export async function GET(request: NextRequest) {
  try {
    const products = await prisma.product.findMany()
    return NextResponse.json({ products })
  } catch (error) {
    return NextResponse.json(
      { error: 'Failed to fetch products' },
      { status: 500 }
    )
  }
}

// POST /api/products
export async function POST(request: NextRequest) {
  try {
    const body = await request.json()
    const product = await prisma.product.create({ data: body })
    return NextResponse.json({ product }, { status: 201 })
  } catch (error) {
    return NextResponse.json(
      { error: 'Failed to create product' },
      { status: 500 }
    )
  }
}

Dynamic Routes

typescript 
// app/api/products/[id]/route.ts
export async function GET(
  request: NextRequest,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params
  const product = await prisma.product.findUnique({ where: { id } })
  
  if (!product) {
    return NextResponse.json(
      { error: 'Product not found' },
      { status: 404 }
    )
  }
  
  return NextResponse.json({ product })
}

Request Handling

  • Request Body: await request.json()
  • Query Parameters: new URL(request.url).searchParams
  • Headers: request.headers.get('Authorization')
  • Cookies: request.cookies.get('session')

Response Helpers

typescript 
// Success response
return NextResponse.json({ data: 'success' })

// Error response
return NextResponse.json(
  { error: 'Not found' },
  { status: 404 }
)

// Redirect
return NextResponse.redirect(new URL('/login', request.url))

// Set headers
return NextResponse.json({ data }, {
  headers: {
    'Cache-Control': 'no-store',
  }
})

Authentication in API Routes

typescript 
import { getServerSession } from 'next-auth'
import { authOptions } from '@/app/api/auth/[...nextauth]/route'

export async function GET(request: NextRequest) {
  const session = await getServerSession(authOptions)
  
  if (!session) {
    return NextResponse.json(
      { error: 'Unauthorized' },
      { status: 401 }
    )
  }
  
  // Access session.user.id, session.user.email, etc.
  return NextResponse.json({ user: session.user })
}

Error Handling

Always wrap API routes in try-catch blocks:

typescript 
export async function GET(request: NextRequest) {
  try {
    // Your logic here
    return NextResponse.json({ success: true })
  } catch (error) {
    console.error('API Error:', error)
    return NextResponse.json(
      { error: 'Internal server error' },
      { status: 500 }
    )
  }
}

Next.js Deployment Considerations

When deploying a Next.js application, consider the following:

1. Static vs Dynamic Rendering

Next.js automatically determines the best rendering strategy:

  • Static Generation: Pages are pre-rendered at build time (fastest)
  • Server-Side Rendering (SSR): Pages are rendered on each request
  • Incremental Static Regeneration (ISR): Static pages are regenerated periodically

Use export const dynamic = 'force-dynamic' to force SSR, or export const revalidate = 60 for ISR.

2. Environment Variables

Next.js has two types of environment variables:

  • Server-side: DATABASE_URL, NEXTAUTH_SECRET (not exposed to browser)
  • Client-side: NEXT_PUBLIC_* (exposed to browser, must be prefixed)
Important: Never expose sensitive data in NEXT_PUBLIC_* variables. They are included in the client bundle.

3. Build Output

The standalone output in next.config.ts creates a minimal server:

  • Includes only necessary files
  • Optimized for Docker deployments
  • Smaller deployment size

4. Image Optimization

Next.js Image Optimization requires a Node.js server in production. For static exports, use unoptimized: true.

5. API Routes

API routes require a Node.js server. They cannot be statically exported. Ensure your hosting provider supports Node.js.

6. Database Connections

In production, use connection pooling for your database:

  • Configure Prisma connection pool size
  • Use environment variables for connection strings
  • Monitor connection limits

7. Caching Strategy

Next.js provides multiple caching layers:

  • Request Memoization: Automatic deduplication of requests
  • Data Cache: Caching of fetch requests
  • Full Route Cache: Caching of rendered pages
  • Router Cache: Client-side route caching

Use cache: 'no-store' or revalidate to control caching behavior.

Troubleshooting

Common Issues

1. Database Connection Error

Problem: Cannot connect to PostgreSQL database

Solutions:

  • Verify DATABASE_URL in .env
  • Ensure PostgreSQL is running
  • Check database credentials
  • Run npm run db:generate

2. Images Not Loading

Problem: Product images show broken links

Solutions:

  • Check public/images/ directory exists
  • Verify image paths in database
  • Ensure NEXT_PUBLIC_BASE_PATH is set correctly if using subdirectory

3. Authentication Not Working

Problem: Users cannot login

Solutions:

  • Verify NEXTAUTH_URL and NEXTAUTH_SECRET
  • Check database has user records
  • Clear browser cookies
  • Check browser console for errors

4. Build Errors

Problem: npm run build fails

Solutions:

  • Check TypeScript errors: npm run lint
  • Ensure all environment variables are set
  • Delete .next folder and rebuild
  • Check for missing dependencies

5. Socket.io Connection Failed

Problem: Real-time chat not working

Solutions:

  • Verify Socket.io server is running
  • Check NEXT_PUBLIC_BASE_PATH configuration
  • Ensure firewall allows WebSocket connections
  • Check browser console for connection errors
  • Verify WebSocket support is enabled on your server

6. Port Already in Use

Problem: Error: Port 3000 is already in use

Solutions:

  • Stop the process using port 3000:
    bash 
    # On Linux/Mac
lsof -ti:3000 | xargs kill -9

# On Windows
netstat -ano | findstr :3000
taskkill /PID [PID] /F
  • Use a different port: PORT=3001 npm run dev

7. Module Not Found Errors

Problem: Cannot find module errors during build or runtime

Solutions:

  • Delete node_modules and package-lock.json
  • Run npm install again
  • Clear Next.js cache: rm -rf .next (or delete .next folder on Windows)
  • Ensure all dependencies are listed in package.json

8. Prisma Client Not Generated

Problem: Prisma Client errors or "Cannot find module @prisma/client"

Solutions:

  • Run npm run db:generate to generate Prisma Client
  • Ensure prisma/schema.prisma is valid
  • Check that Prisma is installed: npm list prisma

9. Environment Variables Not Loading

Problem: Environment variables are undefined or not working

Solutions:

  • Ensure .env file exists in the root directory
  • Restart the development server after changing .env
  • Check variable names match exactly (case-sensitive)
  • For NEXT_PUBLIC_* variables, ensure they're prefixed correctly
  • Verify no extra spaces or quotes in .env file

10. OAuth Login Not Working

Problem: Google/Facebook login fails or redirects incorrectly

Solutions:

  • Verify OAuth credentials in .env file
  • Check redirect URIs match in OAuth provider settings
  • Ensure NEXTAUTH_URL includes basePath if configured
  • Check OAuth provider console for error logs
  • Verify callback URL format: [NEXTAUTH_URL]/api/auth/callback/[provider]

11. Email Not Sending

Problem: Emails are not being sent

Solutions:

  • Verify SMTP credentials in .env file
  • For Gmail, use App Password (not regular password)
  • Check SMTP port (587 for TLS, 465 for SSL)
  • Verify firewall allows outbound SMTP connections
  • Check server logs for email errors
  • Test SMTP connection with a simple script

12. Build Fails with TypeScript Errors

Problem: TypeScript compilation errors during build

Solutions:

  • Run npm run lint to see all errors
  • Fix type errors in the reported files
  • Ensure all imports are correct
  • Check tsconfig.json configuration
  • Update TypeScript types if needed: npm install --save-dev @types/[package]

13. Images Not Optimizing

Problem: Next.js Image optimization not working

Solutions:

  • Ensure images are in public/ directory
  • Check next.config.ts image configuration
  • Verify image domains are allowed in remotePatterns
  • Clear .next/cache directory

14. Slow Performance

Problem: Application is slow or unresponsive

Solutions:

  • Enable production mode: NODE_ENV=production
  • Optimize database queries (add indexes)
  • Enable Next.js caching
  • Use CDN for static assets
  • Optimize images before uploading
  • Check server resources (CPU, RAM, disk)
